# 内容填写模板

一轮交付一个小节即可。继续在飞书写作也可以，但交付时须同时提供可审查的正文、数据和来源。下面的 `[填写]` 都是工作字段，发布前要完成或解释缺失；不要把它们直接作为正式网页内容。

## 0. 框架建设阶段：先交三项

现阶段可以先提交以下内容，不要求一次补齐后续所有字段：

```text
章节/小节：
一句核心发现或要回答的问题：
已有图表、表格或原始材料：
来源链接或文件：
需要说明的问题（可选）：
```

实现方先整理成对应页面/小节模式，登记缺口并协助补齐。详细字段是定稿前的检查清单，不作为开始内容建设的门槛。缺失处保持待补状态，不自动编造数据或结论。

## 1. 定稿前的小节交付包

| 必需项 | 内容 | 建议规模，不是硬性篇幅 |
|---|---|---|
| 一句问题 | 本节要回答什么 | 1 句 |
| 核心发现 | 结论、对象、周期、证据 | 100—200 字 |
| 证据图表 | 图、CSV、统计口径和来源 | 2—4 张有效图表，视证据决定 |
| 数据洞察 | 每个洞察对应图表/表格 ID，解释变化与限制 | 每点 150—300 字，2—3 点 |
| 案例 | 具体项目/组织、机制、结果、来源 | 0—1 个；不能代替总体证据 |
| 行动建议 | 谁、做什么、为何、怎样跟踪 | 2—3 条 |
| 方法与局限 | 统计期、样本、缺失、可比性与不同解释 | 100—200 字 |
| 审阅信息 | 责任人、日期、状态、证据位置 | 每轮更新 |

### 可复制正文

```markdown
---
id: ch02-s01
title_zh: 全球开源活跃地图
title_en: [英文待审]
content_status: draft
data_status: pending-review
author: [填写]
reviewer: [填写]
updated_at: [YYYY-MM-DD]
period_start: [填写]
period_end: [填写]
indicator_ids: [DevScale, TalentDensity, NewcomerGrowth]
---

# 2.1 全球开源活跃地图

## 核心发现
[谁、在什么窗口内、发生了什么变化；用一两项已核验数字支持。]

## 洞察一：[写判断，不写泛泛主题]
[先讲看到的变化，再解释可能原因；相关性与因果推断区分。]

[图表 ID：fig-2-1-3；图注、CSV、单位、来源见图表元数据。]

## 洞察二：[填写]
[正文与对应图表 ID。]

## 方法与局限
[平台覆盖、样本、去重、地理未知率、与上一年度是否可比。]

## 行动建议
- 对[主体]：做[动作]，回应[证据]，用[指标]观察进展。

## 来源与审阅
- [来源名称、URL/文件、统计期、获取日期、版本。]
- 数据复核：[审阅人、日期、结论与未解决问题。]
```

注：`indicator_ids` 只列本节实际观测的指标；标题看起来相关但没有数据支撑时，不自动勾选其覆盖。本文示例 ID 是字段用法，不表示该节三项指标已全部测算。

## 2. 每张图表的填写卡

复制以下字段，为每张准备发布的统计图登记一条。可以交 Markdown 表，也可以填 CSV；实现方统一转入 `data/meta/figures.csv`。

| 字段 | 应填内容 |
|---|---|
| figure_id | 稳定 ID，例如 `fig-2-1-3`，沿用现有文件主干编号 |
| display_number | 正文显示编号，例如原稿“图 2.3”；统一编号时另行映射 |
| title_zh / title_en | 简明、含对象的标题 |
| finding | 一句话读图；结论须能从图中验证 |
| chapter_id / section_id | 归属章与节 |
| indicator_ids | 所用指标代码；补充背景统计可填 `context-statistic` 并解释 |
| chart_type | 趋势/条形/地图/表格/关系图等 |
| data_file | `data/processed/chapterX/fig-…csv` |
| static_file | `figures/chapterX/fig-…svg` 或 PNG，保持同主干名 |
| unit / denominator | 人/账号/仓库/指数/百分比等；比率必须有分母 |
| period_start / period_end | 观测窗口；存量指标另注明“截至”时点 |
| snapshot_at | 数据获取时间，与观测时间分开 |
| source / source_url / source_version | 原始数据或机构材料，而非只填一张截图地址 |
| source_scope | 数据覆盖的平台、地区、对象与样本大小 |
| calculation | 查询/转换脚本路径、版本或明确的可复核计算记录 |
| exclusions / missing | 机器人、镜像、未知地区、缺失值等处理 |
| interaction | 有用的交互，如年份/系列切换；无则写“静态” |
| fallback / alt_text | 可读表格、静态图与文字描述 |
| limitations | 数据或推断的边界 |
| reuse_terms | 自有/第三方，适用许可或来源要求的记录 |
| reviewed_by / reviewed_at / status | 审阅人、日期、研究与发布状态 |

### 现有趋势图的起填示例

```text
figure_id: fig-2-1-3
display_number: 图 2.3（最终显示编号待 A01 统一）
title_zh: 全球五组区域活跃开发者数量趋势
data_file: data/processed/chapter2/fig-2-1-3_five_region_active_developers_trend.csv
years: 2022—2026
unit: 按实际导出标明开发者账号或去重人数；GitHub主范围与多平台补充分别说明
source: 仓库索引记载 OpenDigger、Gitee、AtomGit；需补原始导出与计算记录
interaction: 数量/指数（各区域 2022=100）；年份选择；系列开关
source_scope: 现有CSV的来源组成待核验；主趋势须采用GitHub范围，年度窗口统一上年7月至当年6月，区域成员与重叠规则随数据登记
status: draft / pending-review
```

说明：这一示例仅确认仓库内存在的 CSV 和预览交互，不确认其上游数据已复核。

## 3. 榜单补充模板

除图表卡外，榜单必须填写：

```text
榜单名称与对象粒度：
统计窗口/快照：
指标和算法版本：
候选全集/纳入与排除条件：
组织/地区/项目归属规则：
仓库到项目、项目到组织的映射文件：
名次排序/同分规则：
上一年对照数据与口径是否相同：
新入榜、退出、缺数据、不可比如何显示：
Top N 与公开范围：
数据文件/重算脚本/审阅记录：
```

年度名次变化只在同一可比条件下计算；新入榜不填写虚构的上一年名次；缺测不能作为零分；不同榜单不用同一色阶暗示得分可直接比较。

## 4. 案例与行动建议模板

```text
案例标题与对象：
对象为什么具有代表性、如何选择：
对应 OSDG 支柱/维度：
观察期和证据来源：
实践机制（具体做了什么）：
观察结果（可验证数字或事实）：
无法证明什么、不能外推到哪里：
可供其他参与者采用的做法：
作者/访谈/图片来源及复核：
```

第六章行动表建议列为：`行动主体 | 对应发现/图表 ID | 可执行动作 | 建议跟踪指标 | 适用条件 | 不确定性`。实践建议无需虚构量化目标；主编可另行决定是否设置目标值。

## 5. 每轮提交与验收

提交说明建议：`任务 ID；改了什么；正文位置；数据/素材位置；来源；已核验事项；仍待决定的问题`。一次小节一个审阅单元，便于回退。

工作预览可先接入标明初稿状态的正文与清楚空态，研究验收通过后再进入正式发布页面。实现方检查目录/锚点、单位、图表—CSV一致性、来源、交互与静态降级；主编检查论断、重点、措辞和发布范围。先形成中文定稿，英文沿用相同内容 ID 与图表数据。
