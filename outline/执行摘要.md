# 执行摘要

让每一次开放，成为下一次创造的起点。

开源的发展，既要看有多少人参与、多少成果发布，也要看贡献能否形成影响，成果能否被持续维护和复用。本报告以“从普惠到质量，从参与到影响”为主线，关注代码、模型与数据如何支撑持续共同创造及其公共价值。

## 一个框架，连接目标与证据

借鉴联合国可持续发展目标，以 OSDGs 明确发展方向，以 OSDI 组织观察：四大支柱、十个维度、二十九项指标。各项指标分别解释，不合成一个总分。

## 四个观察，读懂发展质量

**参与规模与协作影响，需要一起看。** 地图说明参与发生在哪里，榜单揭示主体在协作网络中的位置。两者并不总是同向：本期行政区榜中，卡纳塔克邦的开发者更多，英格兰的影响力位次更靠前。理解发展质量，需要把人数、贡献与长期协作联系起来。

行动启示：让人才支持落到真实项目、持续贡献与维护者成长。

证据范围：2025.07—2026.06 · 全球行政区榜；柱长表示开发者数量，徽标表示 OpenRank 位次。

**AI 的开放供给，建立在多层技术协作之上。** 本期项目原榜中，PyTorch、vLLM、CANN 分列第 4、7、13 位。技术全景进一步把项目放回各自的功能位置：应用入口之外，框架、运行、评估与基础工具同样需要持续建设。4.1 从 Agent Infra 与 Model Infra 两类展开这种观察。

行动启示：沿真实依赖寻找共同维护对象，把投入延伸到基础工具。

证据范围：位次来自 3.4 的 2025.07—2026.06 原榜；下方分类为 4.1 的观察框架，不表示项目依赖关系。

**模型与发布账号同步扩张，价值延伸到后续创造。** 同一快照的年度回溯中，模型数增长 58.3%，发布账号数增长 48.4%。中美是地域组织样本中的主要供给力量，模型与配套数据的集中度却不相同。继续沿派生声明观察，可以看到一次发布如何成为后续开发的起点。

行动启示：同时支持关键资产的维护与多元发布者参与，跟踪真实复用。

证据范围：2026-09-13 快照，按创建时间回溯上年同日；仅含快照时仍可见的资产与发布账号，非历年独立存档。

**开放条件与公共价值，需要分别验证。** 材料开放回答“能够获得什么”，许可开放回答“允许怎样使用”。模型开放等级不能代替能力、安全性或社会效益判断。公共价值还要回到具体场景，查看谁在使用、谁能受益，以及成果能否被持续维护。

行动启示：按版本记录开放条件，把公共结果交给使用与受益证据。

证据范围：解释框架，非等级或得分；完整分级说明见 5.3，公共应用与治理见 2.7。

## 三项共同任务，形成行动方向

**支持持续参与与人才成长。** 让新人有入口、贡献能被看见、维护者有接续。关注谁能够留下来，以及如何逐步承担共同建设的责任。

**建设可维护、可复用的开放技术基础。** 把支持延伸到文档、评测、适配与日常维护。沿真实依赖和复用关系找到共同承担工作的伙伴。

**推进透明治理与可验证的公共价值。** 把开放条件落实到具体版本，把公共价值落实到实际使用和结果。让参与规则、决策和维护责任可以查证。

**政府与国际组织**

- 让公共支持延伸到长期维护：支持维护、文档、测试和适配，明确责任人与接续安排。
- 把人才支持连接到真实共建任务：围绕真实项目提供导师、资源和远程参与机会，持续跟踪成长。
- 把开放交付与公共结果分开验收：分别核验开放材料、维护责任与公共使用结果。

**企业与组织**

- 把上游维护纳入产品责任：识别关键依赖，为上游维护安排人员、时间与回馈机制。
- 让每次发布清晰、可用、可追溯：随版本提供材料、许可、运行说明与维护入口。
- 为协作者成长提供时间与认可：为持续贡献预留时间，认可评审、文档、测试等多种角色。

**社区与全球合作**

- 让新人走向共同维护者：让新人从首个任务逐步参与评审、决策与共同维护。
- 围绕共同依赖组织跨地区维护：围绕共同依赖组织适配、评测与多语言文档协作。
- 让公共需求进入共同设计与治理：让本地伙伴和使用者参与设计、试用与评价，把经验带回项目。

## 怎样使用这份报告

第一章建立价值与方法基础，第二至第五章提供生态地图、影响力榜单、技术全景与模型生态观察，第六章连接共同任务与主体行动。可从第一章顺序阅读，也可从目录直接进入关心的小节。

主统计期为 2025.07—2026.06。自然年、月度与平台快照按各图标注分别阅读；不同平台、样本和时间窗口不直接合并。模拟图用于说明观察方式，不据此得出事实结论。第四章深入展开 4.1，其他小节目前提供全景与研究框架。

让开放成果能够被继续使用，让更多人能够参与维护，让公共价值能够被解释、验证和延续。
