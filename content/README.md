# 报告内容架构

本目录把目录、正文位置、页面类型与内容状态集中在[manifest.json](manifest.json)。这是架构工作版，不是已部署的网站；当前交互预览保持现状。

## 阅读结构

执行摘要 → 引言 → 六章（30个小节）→ 附录A/B/C。网站另有首页、指标探索与下载入口，共14个计划页面。页面地址是后续实现目标，不代表已经可以访问。

| 模式 | 用途 |
|---|---|
| 首页与摘要 | 关键发现、圆盘入口、章节导航 |
| 章节阅读 | 统一目录、节锚点、图表、来源及前后节 |
| 指标探索 | 四支柱、十维度、29项指标与正文互相连接 |
| 方法与框架 | 指标、数据来源、方法、限制、DPG评估框架 |
| 宣言 | 核对后的附录B原文 |
| 下载与引用 | 仅列真实生成的PDF、数据包和版本 |

章节按内容使用六种小节模式：目标框架、生态观测、榜单、技术全景、模型研究、行动建议。其块顺序写在清单中，沿用V5“云白阅读、深海蓝发布、青金强调”。

## 怎样填一节

先交三项即可启动：**一句核心发现或问题；相关图表/表格/原始材料；来源及需要说明的问题**。已有正文直接修订，不重新抄一份。编辑、元数据、可读表格与来源核对由实现方逐步补齐；确实影响结论或范围的问题再集中交主编决定。

从第一章的框架说明和2.1样章开始，之后逐节推进。完整要求仍见[填写模板](../planning/TEMPLATES.md)。

## 清单约定

- 路径相对仓库根目录；已有正文继续存放在`chapters/`、`appendices/`和`outline/`。
- `source: null`表示没有可直接使用的正文，不是空白已完成页。`missing`、`rewrite`、`pending-source-check`分别表示缺稿、重写与源文待核对。
- `source_heading`精确引用同一文件中的现有标题。第六章五节共用一份原稿，不复制五份文本。
- `source_ids`用于同源呈现，例如指标探索引用1.2/1.3；ID与锚点稳定，显示标题可随编辑调整。
- `draft`仅表示已有初稿，不等于数据审阅通过；目前研究审阅状态均保留待复核。
- 缺稿为3.6、4.2及第五章三个小节；引言另行重写；附录B只登记指定权威链接和旧快照参考，核对前不自动发布旧原文。
- 英文后续沿用同一内容ID；现阶段不伪造英文正文或可用下载。

## 架构与发布分别验收

框架可以先连接真实初稿，缺稿展示清楚的待补状态。进入正式发布前，仍须逐节完成数据、编辑、交互/打印验证和主编定稿。本次新增索引与填写模式，没有实现渲染器、PDF管线或新路由部署。

已确定的方法见[决策记录](../planning/DECISIONS.md)，具体算法与数据包证据在各节接入时完善，不阻挡框架先成形。
