# 章节写作与内容复用规范

## 1. 共用逻辑，标题随研究问题变化

全书采用“问题引入—证据展开—解释判断—行动衔接”的内容逻辑。每节保留一句核心问题、一句主要判断、一组关键证据和必要的方法边界；实际标题用读者正在关心的问题或观点表达，不机械重复“核心发现—数据洞察—策略建议”。

第一章按“为什么研究—目标是什么—怎样观察”推进。1.1、1.2、1.3 均采用四段主体加资料说明：问题或故事、核心概念与结构、证据或方法边界、应用及下一节衔接。允许表格、案例和图解承担不同功能，不要求每节字数或图数相同。

## 2. 四个核心章节的建议写法

本表是后续修订建议，本轮不改写第二至第五章原稿或已有数据。

| 章节 | 适合的叙事顺序 | 小节标题示例 | 方法信息放在哪里 |
|---|---|---|---|
| GOSO 全球开源生态观测地图 | 地图呈现格局 → 比较变化 → 解释参与结构 → 指出值得关注的问题 | “参与版图怎样变化”“规模增长发生在哪里”“哪些群体仍不可见” | 图注标明地域、平台、年度与未知项；详细规则链接附录 |
| GOSR 全球开源影响力排行榜 | 先交代榜单范围 → 展示排名 → 解释结构和变化 → 用案例说明贡献路径 | “谁进入了已核验样本的前列”“排名变化背后的贡献结构” | 榜前简明说明主体、样本、指标；下载区提供映射与方法版本 |
| GOSL 全球开源技术全景洞察 | 提出技术问题 → 展示分类与关系 → 观察关键节点和演进 → 讨论机会与约束 | “技术栈怎样组织协作”“哪些连接正在形成”“维护与依赖的压力在哪里” | 注明分类版本、项目清单、关系定义及覆盖 |
| GOSM 全球开源大模型发展洞察 | 供给格局 → 采用与复用 → 开放和治理条件 → 生态演进含义 | “开放供给由谁构建”“哪些模型成为再创造的起点”“开放到什么程度” | 区分版本、模型系列、开放资格、下载窗口、派生关系与算法成熟度 |

每个小节可以以一段“这意味着什么”结束；跨主体、跨章节的系统行动建议集中到第六章。证据不足的小节先列研究问题和待补数据，不强行写出结论或政策建议。

## 3. 为阅读、演示和影片保留可复用单元

每个内容单元包含：稳定编号、核心问题、一句话判断、主图或关键表、证据链接、口径说明、所属章节和目标受众。先维护事实与引用，再为不同载体改写表达。

| 载体 | 保留什么 | 怎样改写 |
|---|---|---|
| 报告全文 | 论证、证据、解释、边界和引用 | 完整展开，方法集中链接 |
| 互动演示 | 一页一个问题或观点，配主图与可展开的资料入口 | 减少正文段落，保留口径和来源入口 |
| 宣传影片 | 有证据支持的故事、变化和报告核心价值 | 数字保留时间与对象提示；避免把框架规划讲成已完成成果 |
| 发布材料 | 核心定位、框架图、关键结果及访问入口 | 使用同一术语与事实来源，随报告版本更新 |
