# 2.2 全球开源贡献地图（C-Map）打磨方案 · 审阅稿

日期：2026-10-15。**历史方案，已由 [2026-10-20 出版修订](cmap-publication-revision-20261020.md) 取代。下列自然年、虚构机制与待补计划不再是当前 2.2 的实施依据。**

## 一、推荐定位

**副标题：从参与规模到协作贡献。**

**核心问题：活跃力量在哪里形成可观测的协作贡献，参与版图与贡献版图有哪些差异？**

建议将主张收束为：**参与版图与贡献版图并不重合；全球开源能力建设需要同时看见贡献规模、变化与区域差异。**

2.1 回答“谁在参与、在哪里参与”，2.2 回答“这些地区呈现怎样的协作贡献”；2.3 再转向“项目影响力在哪里积累”。2.2 保留宏观分析，不提前展开第三章的个人／机构榜单，也不将 2.5 的跨国贡献流向并入本节。

采用已确认的“全球 → 五域 → 中国”阅读路径，三幅主图、三条发现、三项行动建议。正文建议约 1,600—2,000 字，方法与精确数据放在就近展开的证据层。

## 二、核心发现中的指标定位段

> 本节对应 OSDGs 的 X2“技术产出与开放供给”、2.1“代码产出”，以 OSDI 的代码协作贡献度（OpenRankContrib）为主指标，并结合 X1 的活跃开发者规模（DevScale）观察参与规模与贡献分布的差异，呼应 SDG 9 与 SDG 17。地区贡献份额、年度变化和平均贡献属于诊断性派生分析，不另设综合评分。正式测算前，须核实源数据的 OpenRank 算法类型、年度聚合与地域归属规则；参与人数与贡献值只有在范围和窗口一致时才可联算。

此段沿用第一章现有指标词典，**不先修改 OSDI 定义**。OpenDigger 官方分别定义社区 OpenRank 贡献度和全域 OpenRank 影响力；不能只凭 OpenShare 的“开发者贡献度”界面名称认定已经完成字段映射。若数据实际对应另一算法，应修正数据映射或研究措辞，再决定是否调整第一章。

拟记录的指标反馈：

| 类型 | 本节使用 | 反馈到第一章 |
|---|---|---|
| 主指标 | OpenRankContrib | 补全源算法类型、版本、时间聚合与跨社区／平台规则 |
| 辅助指标 | DevScale | 与 2.1 共用窗口、平台和地域编码，避免分母漂移 |
| 派生诊断 | 贡献总量变化；同范围贡献份额；每活跃开发者平均贡献 | 先保留为诊断，不另增北极星指标，不解释为生产率或个人能力 |
| 后续章节 | OpenRankInflu；GlobalCollabShare | 分别交给 2.3 和 2.5，不把项目影响力与贡献值相除为“转化率” |
| 潜在补充 | 持续贡献、评审／维护参与的证据 | 本节聚合数据不足以证实留存或维护能力；先列证据需求，再考虑是否增指标 |

## 三、三个故事与三幅交互图

### 故事一：贡献版图与参与版图并不重合

**图 2-2-1：全球开源协作贡献全景图。**

- 主问题：全球协作贡献分布在哪里？相近的参与规模是否对应相近的贡献表现？
- 默认画面：与 2.1 同源同形态的世界地图＋贡献排行＋选中地区详情。地图以 OpenRank 值着色，图例明确单位；点击中国可下钻并有清晰返回入口。
- 信息补充：选中地区同时显示同窗口活跃规模、贡献值和两种排序，避免把两个不同单位挤入一根柱。设置“参与／贡献对照”视图，显示选定国家的并排排名或并列数值。
- 空间利用：下方放全球贡献总量的五年小趋势；点击选定国家后，仅在已取得相同口径历史记录时切换该国趋势，缺失则清楚显示“历史待补”。
- 可核实的观察入口：2025 自然年 GitHub 数据中，德国活跃规模排第 5、贡献度排第 2；印度分别为第 2 与第 5；巴西分别为第 4 与第 8。它们支持“分布不同”的描述，不足以直接证明产业、治理、教育或开发者能力的原因。
- 对全球南方的表达：让其已发生的贡献被看见，同时追问贡献认可、导师支持与进入持续协作的条件；不从相对排名推断“质量不足”。

### 故事二：同时观察贡献积累的规模与节奏

**图 2-2-2：全球五域贡献规模与五年演进。**

- 主问题：哪些比较组积累了较大贡献，哪些呈现变化？新增参与与贡献变化是否同向？
- 默认画面：美国、欧洲、中国、印度、全球南方代表六国的贡献规模对照；同年 DevScale 用独立的小图对照，不混用坐标轴。五组沿用 2.1 定义，并公开组成员。
- 趋势页：五年绝对值／起始年=100 两种视图互切，点击突出一组；同一时段和度量内比较规模与相对变化。各页保持同一画幅，不滚动。
- 现阶段实施选择：先以 2025 自然年和对应 2021—2025 序列建立与 2.1 一致的打样。当前公开 JSON 已有全球、美国、中国五年贡献序列；印度、六国组、欧洲的同口径完整五年数据尚未取得，保留位置并标“待补”，不拼接旧序列。欧洲当前合计也须有明确成员清单。
- 原仓库 2022—2026 五组表继续保留在证据层，标明“原稿序列，口径待对齐”。它不能与 2021—2025 自然年拼接，也不能默认为 GitHub 单平台数据。
- 默认只展示 GitHub。Gitee／AtomGit 的贡献补充需取得实际贡献度及可比性依据后再开放切换；2.1 的约 120 万人数不能换算成 OpenRank。
- 洞察方向：既看长期积累，也看各组自身变化；“增长是否来自持续协作”“贡献是否集中于少数维护者”作为下一步机制研究，不能从年度总值直接宣称成立。

### 故事三：区域贡献规模与平均表现提供不同的观察线索

**图 2-2-3：中国开源贡献结构与区域节点。**

- 主问题：一个国家内部，贡献的集中地与平均贡献表现是否一致？这能为区域合作提供什么线索？
- 默认画面：34 个省级地区贡献地图＋分页排行＋地区详情。底图、台湾省及港澳呈现、下钻与返回行为沿用已接受的 V-Map。
- 详情区：贡献值、同口径活跃规模、全国份额（分母核验后）、已取得的同比；全国实际五年趋势提供背景，未取得省级历史时不冒充省级趋势。
- 第二视图：在同范围联算验证后，显示“贡献规模／平均贡献”切换，或“活跃规模×贡献总量”散点对照。点击地图、排行、散点选中同一地区。平均值同时显示分母，小基数地区明确提示，不把数值直接命名为“效率高地”。
- 原表处理：现有“人均 OpenRank Top 10”不再作为独立大表占一屏，保留为来源对照，新增完整 34 地区语义表供下载／分页核对。不得将前十样本宣称为全部地区。
- 需要调整的判断：新取得的完整省级数据中，小基数地区可得到很高的平均值。因此原稿“浙江、台湾、上海最高”的表述不能原样沿用；应区分原表筛选样本和全体地区，并核验分母及筛选依据。
- 洞察方向：以中国展示区域内部的多样性，提出可以跨国借鉴的“节点分工与长期合作”研究路径。产业、高校和政策的机制解释需由项目案例支持，不从横截面地图直接推断“贡献向中西部扩散”。

三幅图均使用已接受的品牌、编号、一屏画布、主题与全屏／退出规则。主图保留核心判断，详细方法放在相邻证据层；不新增自动流动连线、连续动效或图内纵向滚动。

## 四、正文统一模板与建议段落

1. **核心发现**：一句主判断＋三条故事摘要＋上面的指标定位段。
2. **数据洞察**：每个故事按照“判断句 → 图 → 两三项关键证据 → 解释与边界 → 对行动的含义”写作；每图只承载一个主要问题。
3. **策略建议**：三项动作分别对应识别、支持与组织协作。
4. **指标反馈与待补证据**：集中列出影响结论的缺口；用一句话过渡到 2.3。

| 行动方向 | 建议写法 | 可观察的后续进展 |
|---|---|---|
| 让持续协作获得认可与支持 | 公共资助方、基金会和企业共同认可评审、维护、文档与指导等贡献，结合 OpenRank 和项目证据观察，避免单一分数替代判断 | 支持计划是否覆盖这些角色；持续参与／维护记录，需另补数据 |
| 支持全球南方成为共同维护者 | 将合作从短期参与活动延伸至导师制、联合维护与长期项目角色；由当地社区共同设计项目并参与决策 | 联合维护安排、持续贡献及跨地区协作证据；具体测量与 2.5 衔接 |
| 用区域节点承接长期协作 | 以中国为区域观察实例，探索高校、企业与社区围绕真实项目组织协作；总结可供其他国家检验的经验 | 具名节点、合作项目、角色分工和连续记录；案例待作者补充 |

过渡到 2.3 的建议句：**贡献来自哪些地区，与项目影响力归属于哪些地区，是两个不同问题。下一节沿项目维度观察影响力的积累与分布。**

## 五、本轮已核实的证据与需要修正的边界

### 5.1 三套中国贡献度必须分开

| 数据层 | 年度／窗口 | 中国贡献值（OpenRank） | 本轮用途 |
|---|---|---:|---|
| 原仓库五组表 | 标签为 2026，具体聚合／覆盖待核 | 4,429,200.83 | 保留原稿证据，不直接作为 GitHub 全球地图数值 |
| OpenShare 自然年 | 2025-01-01 至 2025-12-31 | 1,210,375.59 | 推荐本次与 2.1 配套的打样基线 |
| OpenShare 报告年度 | 2025-07-01 至 2026-06-30 | 936,846.83 | 单列记录，为统一正式报告年度做准备 |

上述差异已实际取得，不是对某一数据源判错。**“中国贡献超过美国”“中国增长 47.2%”暂作为原稿表内观察，不能直接提升为当前统一口径的全球结论。** 正式 2026 报告仍以第一章规定的报告年度为目标；本次采用自然年是打样的一致性选择，后续要连同 2.1 一起切换，不能只换 2.2 的分子。

### 5.2 数据覆盖

- OpenShare 自然年贡献明细：236 个国家／地区条目，34 个中国省级地区条目；全球、美国、中国具有 2021—2025 五年贡献序列。
- 自然年全球贡献总值为 18,943,529.85，地域表合计 18,523,442.24，差额 420,087.61。差额原因尚未核实，不能自动归入未知地域，也不将可识别地区份额重归一化后称为全球份额。
- 中国省级贡献合计为 1,210,375.60，与全国值相差 0.01，记录舍入差，不随意改写原数。
- 原仓库两份 2.2 CSV 本轮重新读取，内容与 Preview 留存一致；这不意味着算法类型、时间窗和跨平台口径已核验。
- 新取得数据只进入本轮审阅证据目录，未替换报告原表。抓取时间、原始值、URL 与 SHA-256 见 `content/reviews/cmap-2-2/source-register.json`。

## 六、集中补充项与推进顺序

优先只补三组会改变结论的材料，允许由报告负责人统一协调：

| 优先级 | 要补什么 | 决定什么 |
|---|---|---|
| 1 | OpenShare／原稿贡献字段的算法类型、版本、年度汇总、地域归属、平台覆盖；原稿 443 万的构成及与源数据对照 | 能否正式映射 OpenRankContrib、是否成立跨平台比较与排名结论 |
| 2 | 欧洲成员清单；五组同窗口 5 年序列；如保留人均指标，贡献分子与活跃分母的对象范围、筛选阈值和匹配方式 | 五域趋势完整性、平均贡献解释、2.1／2.2 联算是否成立 |
| 3 | 1—2 个可核验的长期协作案例，优先一个全球南方共建案例、一个中国区域节点案例 | 将“产业／教育／治理条件”的解释从假设提升为有支持的洞察 |

**本轮评审重点**：是否同意“参与版图与贡献版图的差异”作为主张；是否同意三幅图沿用三层尺度，并把人均值降为有边界的辅助诊断；是否同意先用与 2.1 一致的 2025 GitHub 基线打样，正式年度与多平台结论在对齐后接入。

评审通过后，先实现三幅交互图和对应全文；缺失内容以明确占位保留，再做一屏、全屏、主题、键盘与数据回归检查，交付可评审版本。当前工作仅登记基线和本方案。
