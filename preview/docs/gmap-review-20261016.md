# 2.7 G-Map 五图审阅稿 · 2026-10-16

本轮落实已批准的核心问题、五组图和三个行动主张，仅更新既有私人审阅 Site。正式报告 GitHub 仓库与 Pages 未改。

核心问题：全球开源由谁共同治理，如何获得持续支持，又怎样形成可验证的公共价值？

## 结构与交互

1. 全球治理与公共品全景：治理组织、共同维护、公共应用；主体筛选、地区定位及隐藏模拟数据。沿用 V/A-Map 同一几何，中国包含台湾省。
2. 治理结构与制度演进：实践矩阵、治理角色、基金会五年演进、许可选择与木兰案例。可选年份与指标，矩阵逐项展开。
3. 维护与可持续支持：依赖与资金支持散点、维护负担、支持结构、人员接续。参考线为 6 / 12 / 18 / 24 个月，虚构项目可逐项选择。
4. 公共服务与受益证据：八类场景的嵌套证据层、本地共建路径、两例效果观察。前后变化保留非因果解释。
5. AI 时代的开源责任：代码—模型—数据责任检查、AI 贡献与人工评审、Agent 权限安排。逐项展开，不设任意总分。

共 17 个主视图。延续 1280×820 单屏画布、既有字体与配色、图内来源说明和统一全屏机制。同一 DOM 在阅读页和全屏间移动，退出恢复位置与状态；键盘可操作地图点和趋势点。

三个行动主张：建立可追溯的治理公共底座；为长期维护配置持续资源；让公共应用成为本地共同创造。

## 数据边界

新增地理分布、治理角色和实践、维护支持、公共应用及 AI 责任数据均为合成数据，显著标注“模拟演示 / 非实测 / 非预测”。地图不存在已核验数据时显示空缺，不把缺失填零，不赋予真实组织或项目模拟结论。

三份原 CSV 从当前 Site 同源报告数据复制，逐字节保持一致；旧文件名 2-6 保留，展示编号改为 2-7-2。基金会活跃仓库 3,163→3,350，约 +5.9%；OpenRank 份额 2.63%→2.93%，+0.30 个百分点。既有数据仍待样本、分母、时间窗与复现核验，不推断治理效率。

许可五类数量无总体分母，不推算合规覆盖；木兰累计活跃与当年活跃分开。治理角色不从贡献份额推断。公共证据层嵌套、不相加；名录认可与部署效果分开。AI 覆盖使用每项 100 个适用且已检查模拟样本，未检查规模未设定。

## 文件与后续替换

- 正文：`portal-source/web/gmap_content.py`
- 交互：`portal-source/web/gmap.js`
- 样式：`portal-source/web/gmap.css`，继承 A-Map 的独立命名空间样式，再添加治理图组布局。
- 数据：`portal-source/content/gmap/simulation.json`、`data.js`、三个原 CSV、`source-manifest.json`。
- 数据准备：`python tools/prepare-gmap.py`，以同目录模拟 JSON 为输入，读取既有报告 CSV 和地图几何，重新生成载荷并保留来源元数据。
- 构建：`python tools/build-aligned.py`。
- DOM 检查：提供 jsdom 后，`node tools/check-gmap.cjs`。可用 `NODE_PATH` 指向 QA 依赖目录；运行时 Site 无 npm 依赖。

真实数据接入时同步修改证据状态、样本、分母、时间窗、来源与解读。未发现、未检查、仅自述、不适用和未知地域应分别保存。
