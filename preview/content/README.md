# 报告内容架构

本目录把目录、正文位置、页面类型与内容状态集中在[manifest.json](manifest.json)。这是架构工作版。阅读框架已实现并同步原私密预览；完整正文与研究结果逐章整理。

## 阅读结构

执行摘要 → 引言 → 六章（30个小节）→ 附录A/B/C。网站保留原首页与指标探索，新增中英文各13个阅读页面。章节问题、呈现计划与源稿均已连接，完整正文尚未全部接入。

| 模式 | 用途 |
|---|---|
| 首页与摘要 | 关键发现、圆盘入口、章节导航 |
| 章节阅读 | 统一目录、节锚点、图表、来源及前后节 |
| 指标探索 | 四支柱、十维度、29项指标与正文互相连接 |
| 方法与框架 | 指标、数据来源、方法、限制、DPG评估框架 |
| 宣言 | 核对后的附录B原文 |
| 下载与引用 | 仅列真实生成的PDF、数据包和版本 |

章节按内容使用六种小节模式：目标框架、生态观测、榜单、技术全景、模型研究、行动建议。其块顺序写在清单中，沿用V5“云白阅读、深海蓝发布、青金强调”。

## 怎样填一节

先交三项即可启动：**一句核心发现或问题；相关图表/表格/原始材料；来源及需要说明的问题**。已有正文直接修订，不重新抄一份。编辑、元数据、可读表格与来源核对由实现方逐步补齐；确实影响结论或范围的问题再集中交主编决定。

从第一章的框架说明和2.1样章开始，之后逐节推进。完整要求仍见[填写模板](../planning/TEMPLATES.md)。

## 清单约定

- schema_version 2.0 延续原章节与小节 ID，增加双语标题、研究问题、呈现计划与可生成路由。
- `source_path` 指向仓库内正文或结构稿；`status` 区分 draft、outline 与 source-confirmed。`data_status` 和 `research_status` 独立保留待复核。
- 第六章五节共用一个源稿；`source_heading` 精确对应该文件标题。
- 缺稿已建立结构文件，仍标 outline，不表示实证正文已完成。独立引言已有编辑初稿；附录 B 等待指定源文核对。
- `framework_entry` 继续关联原首页圆盘，正文通过同一内容 ID 衔接指标探索。
- 原有 presentation、section_patterns、minimum_submission 和 workflow 约定保留。生成与同步见 [web/README.md](../web/README.md)。

## 架构与发布分别验收

框架可以先连接真实初稿，缺稿展示清楚的待补状态。进入正式发布前，仍须逐节完成数据、编辑、交互/打印验证和主编定稿。本轮已实现静态阅读框架和新路由；完整正文渲染、正式 PDF 与浏览器实际验收继续按任务推进。

已确定的方法见[决策记录](../planning/DECISIONS.md)，具体算法与数据包证据在各节接入时完善，不阻挡框架先成形。
