# 附录 A：指标体系与数据来源

本报告构建开源发展指标体系（Open Source Development Indicators，OSDI），以开源发展目标（Open Source Development Goals，OSDGs）为价值导向，将全球开源生态中的人才参与、技术贡献、项目影响、国际协作、生态治理和数字资产转化为可测量、可比较的指标。

该指标体系为第二章“全球开源生态观测地图”、第三章“全球开源影响力排行榜”和第四章“全球开源技术全景洞察”提供统一的方法论与数据基础，支持从生态规模观测、贡献质量分析到主体影响力评价的全过程研究。

## 1. 指标体系来源与理论基础

本报告的指标体系以《信息技术 开源治理》系列标准为基础，结合OSDGs框架、OpenRank和ModelRank评价模型以及人工智能时代的开源资产特征，形成“活跃度—贡献度—影响力—治理与资产”的递进式评价框架。其中，OpenRank用于衡量开源协作网络中的贡献与影响，ModelRank用于衡量模型复用网络中的影响力。

指标体系主要遵循三项原则：

- **科学性**：从开发者行为和协作网络出发，综合衡量规模、质量、结构与影响。
- **可操作性**：采用公开数据、平台接口和可复现算法，确保指标可获取、可计算。
- **可比性**：统一行为定义、统计周期和计算规则，支持跨年度、跨区域和跨主体比较。

## 3. 核心指标体系

本报告使用的指标主要分为活跃度、贡献度、影响力、人才与多样性、治理与数字资产五类。

### 3.1 活跃度

活跃度用于衡量开发者和项目的实际参与规模。

<sheet sheet-id="vbC6vR" token="AkvfsxJOBhmbqmt1zr0c42Synwg"></sheet>

### 3.2 OpenRank贡献度

OpenRank贡献度基于项目或社区内部的协作网络，综合开发者参与的行为类型、协作对象和行为质量，衡量开发者在项目中的实际贡献价值。

该指标主要用于：

- 观察不同国家和地区的开发者贡献规模；
- 识别项目和社区中的核心贡献者；
- 衡量开发者规模向高质量贡献的转化程度；
- 分析开发者对不同国家项目的跨国贡献流向。

### 3.3 OpenRank影响力

OpenRank影响力基于全球开源协作网络，衡量开发者、项目、组织和地区在全球生态中的网络地位与系统性影响。

<sheet sheet-id="hJg6W8" token="AkvfsxJOBhmbqmt1zr0c42Synwg"></sheet>

#### 3.4 ModelRank模型影响力

ModelRank基于模型派生与复用关系构建评价网络，结合累计派生关系、当月新增复用关系和模型使用信号，衡量模型作为后续开发基础的影响力。一个模型的影响力不仅取决于复用规模，也取决于复用它的模型在网络中的影响。

### 3.5 开源人才与贡献多样性

采用前5%作为开源人才识别范围，能够兼顾核心人才识别与统计覆盖度，用于比较不同国家、地区和城市的核心人才规模及其变化。

## 4. 数据来源与计算说明

本报告的数据主要来自以下平台和公开数据源。

<sheet sheet-id="qJtcdB" token="AkvfsxJOBhmbqmt1zr0c42Synwg"></sheet>

OpenDigger负责对多平台开源协作行为进行持续采集、清洗和标准化处理，并提供OpenRank指标计算所需的数据基础。

本报告采用统一的12个月统计周期。主编已确认，2022—2026年主年度序列的每个报告年度均覆盖上年7月1日至当年6月30日。例如，2022报告年度对应2021年7月1日至2022年6月30日，2026报告年度对应2025年7月1日至2026年6月30日。逐年起止日期见[data/README.md](../data/README.md)。

使用“截至2026年7月”表述的地图和榜单，若展示年度活动指标，应明确其对应的最近完整报告期；若展示存量，应另注明实际截至日期。外部补充快照保留原始观测期间，不改写为本报告期。周期定义已经主编确认，现有数据文件与该定义的一致性仍需逐图核验，同时检查平台覆盖、对象定义和算法版本的年度可比性。

平台账号按照“平台—用户ID”去重。主编于2026年10月11日确认：已有并经过验证的跨平台开发者身份映射覆盖GitHub、Gitee、AtomGit和GitLab，支持2022—2026全部报告年度。在映射适用范围内，开发者人数采用跨平台身份去重，同时保留平台账号数作为核对量。平台覆盖不等于所有账号均已成功映射，不能直接将各平台账号数相加后称为开发者人数。相关数据说明需登记映射方法与版本、验证记录、匹配覆盖率、未匹配及冲突处理，以及GitLab的实例范围。该确认尚不代表现有聚合数据已应用映射，实际流程将在逐图核验时检查。

主编已确认：现有开发者统计已识别并剔除机器人和自动化服务账号。人数指标应注明这一排除范围，配套账号数应标明剔除前或剔除后；识别规则、版本及各平台各年度的剔除数量在数据交付时登记并逐图核验。该确认不表示全部自动化账号均已被识别，也不自动适用于OpenRank网络、项目贡献或影响力计算的事件处理。人类使用AI辅助工具不直接作为机器人判据，本次确认不涉及AI生成代码检测。

仓库按照“平台—仓库ID”去重。主编已确认，目前项目—仓库对应关系只有部分覆盖，尚不能认定跨平台镜像和多仓库项目均已识别。未匹配仓库不自动作为独立项目；映射需登记关系类型、验证依据、有效年度、版本和覆盖分母。GitHub主范围与多平台补充分别说明映射覆盖，项目身份映射不将其他平台活动并入GitHub主范围。项目级指标聚合、重复事件和跨年度映射变化仍待核定，不直接相加仓库OpenRank值。主编已决定：本期先做已核验项目的样本榜，逐步扩充；未映射记录保留仓库层统计，不默认作为独立项目或零分项目。榜单明确标注样本及平台范围，不解释为完整全球项目排名。每版冻结项目清单、映射与计算版本以及纳入/排除依据，扩充时记录版本变化。

项目映射覆盖率以明确的候选范围为分母；候选母体不完整时披露已核验数量和已知缺口，不宣称全球项目覆盖率。历史名次比较需核定各年度有效项目边界和可比样本，新纳入样本不等于新诞生项目。主编已确认：已核验项目保留了2022—2026各年度有效的项目—仓库映射，可按当年项目边界统计。有效年度、映射版本及归属变化依据随数据包登记，不把当前项目边界无说明地回填历史；不存在于某年度与缺失映射分别标记。该能力仅适用于已有核验映射的样本，历史名次仍须核对候选集合、平台范围、算法和计算结果。本轮不据此改写现有项目统计。

开发者国家和地区归属依据已由主编确认：**使用公开个人资料中的所在地，经标准化处理。** 该属性反映公开资料所载所在地，不等同于国籍、出生地或雇主所在地，也不代表已独立验证实际居住地。数据说明需登记位置来源、采集/快照时间和标准化方法/版本，并区分国家级与城市级等可识别粒度。主编已确认：2022—2026年地区统计分别使用各报告年度对应的历史位置快照，不以同一最新位置快照覆盖所有年份。具体快照日期、平台及版本随数据包登记，不假定均采集于报告期末6月30日。位置表示快照时点公开资料所载所在地，不代表全年居住地，年度间位置变化也可能影响地区分布。GitHub主范围使用该年度GitHub快照，多平台补充记录各自快照时点；跨平台位置冲突由同年度的原始位置字段、标准化结果与历史快照时点进行核验并记录依据；无法消解的冲突在相应层级标为未知，不预设固定平台优先级。国家一致但城市仍冲突时保留国家归属，仅城市标为未知；国家也无法确定时不分配具体国家或城市。同一开发者在同一层级只计数一次，未知部分仍计入总量。该消解结果用于多平台补充，不自动回写GitHub主范围。历史位置缺失不自动用最新位置回填，按下述未知地区规则处理。主编已决定：位置缺失或无法可靠识别的开发者仍计入全球总量，地区未知单列；这些记录仍须满足相应指标的活动、去重和机器人排除条件。国家可识别但城市不可识别的记录参与国家级统计，在城市级保留为未知。

各地理层级在同一平台范围、报告年度与计数单位下分别核对：全球总量等于已定位数量与未知数量之和，位置识别率为已定位数量除以全球总量。每个对象在同一层级仅计入一个地区或未知类别，各年披露识别率。国家或城市“占全球比例”以含未知地区的全球总量为分母，并显示未知量或占比；若仅呈现已定位样本内部构成，须另标“已定位开发者中的占比”，不混称全球占比。分母为零时记为不适用。GitHub主范围与各多平台补充范围分别计算，不混用分子与分母。

项目归属在现有初稿中按发起组织或主要维护组织所在地确定，其最终规则与组织归属缺失处理仍待A02核定，不由开发者所在地规则自动决定。

不同平台在事件类型、用户标识和地理字段方面存在差异。主编已确认GitHub、Gitee、AtomGit和GitLab的开发者活动数据均支持2022—2026年连续、跨地区的同口径比较；实际采集覆盖、事件对应和计算流程将在样章数据核验时检查。

主编已决定：**代码生态全球主榜与主趋势以GitHub为主范围，Gitee、AtomGit、GitLab作为补充。** 主范围各地区、各年度统一纳入GitHub活动记录，并采用既定报告窗口和统一指标方法；人数的计数单位与去重规则随指标标明。跨平台身份映射不将其他平台活动并入GitHub主范围。GitHub观测结果明确标注平台范围，不表述为全部全球平台的完整总量。

补充分析逐图列明实际平台组合；多平台开发者人数在适用的身份映射范围内去重，保留账号数供核对，并与主榜分别展示和提供下载。不能把仅某地区采用的多平台合计直接并入GitHub主榜。已有混合来源图表须在样章核验时拆分或重新导出GitHub主范围结果，经核验的多平台结果可单列补充，本轮不直接修改现有数值。缺少可靠省市位置数据的平台不进入相应城市级细分，适用范围和缺失处理随图说明。
