# 附录 A：指标体系与数据来源

本报告构建开源发展指标体系（Open Source Development Indicators，OSDI），以开源发展目标（Open Source Development Goals，OSDGs）为价值导向，将全球开源生态中的人才参与、技术贡献、项目影响、国际协作、生态治理和数字资产转化为可测量、可比较的指标。

该指标体系为第二章“全球开源生态观测地图”、第三章“全球开源影响力排行榜”和第四章“全球开源技术全景洞察”提供统一的方法论与数据基础，支持从生态规模观测、贡献质量分析到主体影响力评价的全过程研究。

## 1. 指标体系来源与理论基础

本报告的指标体系以《信息技术 开源治理》系列标准为基础，结合OSDGs框架、OpenRank和ModelRank评价模型以及人工智能时代的开源资产特征，形成“活跃度—贡献度—影响力—治理与资产”的递进式评价框架。其中，OpenRank用于衡量开源协作网络中的贡献与影响，ModelRank用于衡量模型复用网络中的影响力。

指标体系主要遵循三项原则：

- **科学性**：从开发者行为和协作网络出发，综合衡量规模、质量、结构与影响。
- **可操作性**：采用公开数据、平台接口和可复现算法，确保指标可获取、可计算。
- **可比性**：统一行为定义、统计周期和计算规则，支持跨年度、跨区域和跨主体比较。

## 3. 核心指标体系

本报告使用的指标主要分为活跃度、贡献度、影响力、人才与多样性、治理与数字资产五类。

### 3.1 活跃度

活跃度用于衡量开发者和项目的实际参与规模。

<sheet sheet-id="vbC6vR" token="AkvfsxJOBhmbqmt1zr0c42Synwg"></sheet>

### 3.2 OpenRank贡献度

OpenRank贡献度基于项目或社区内部的协作网络，综合开发者参与的行为类型、协作对象和行为质量，衡量开发者在项目中的实际贡献价值。

该指标主要用于：

- 观察不同国家和地区的开发者贡献规模；
- 识别项目和社区中的核心贡献者；
- 衡量开发者规模向高质量贡献的转化程度；
- 分析开发者对不同国家项目的跨国贡献流向。

### 3.3 OpenRank影响力

OpenRank影响力基于全球开源协作网络，衡量开发者、项目、组织和地区在全球生态中的网络地位与系统性影响。

<sheet sheet-id="hJg6W8" token="AkvfsxJOBhmbqmt1zr0c42Synwg"></sheet>

#### 3.4 ModelRank模型影响力

ModelRank基于模型派生与复用关系构建评价网络，结合累计派生关系、当月新增复用关系和模型使用信号，衡量模型作为后续开发基础的影响力。一个模型的影响力不仅取决于复用规模，也取决于复用它的模型在网络中的影响。

<sheet sheet-id="96be4o" token="AkvfsxJOBhmbqmt1zr0c42Synwg"></sheet>

### 3.5 开源人才与贡献多样性

采用前5%作为开源人才识别范围，能够兼顾核心人才识别与统计覆盖度，用于比较不同国家、地区和城市的核心人才规模及其变化。

### 3.6 治理与数字资产

代码仓库、模型和数据集共同构成本报告所观测的开源数字资产。基金会和许可证指标用于观察开源项目的治理基础与制度环境。

## 4. 数据来源与计算说明

本报告的数据主要来自以下平台和公开数据源。

<sheet sheet-id="qJtcdB" token="AkvfsxJOBhmbqmt1zr0c42Synwg"></sheet>

OpenDigger负责对多平台开源协作行为进行持续采集、清洗和标准化处理，并提供OpenRank指标计算所需的数据基础。

本报告采用统一的12个月统计周期。主编已确认，2022—2026年主年度序列的每个报告年度均覆盖上年7月1日至当年6月30日。例如，2022报告年度对应2021年7月1日至2022年6月30日，2026报告年度对应2025年7月1日至2026年6月30日。逐年起止日期见[data/README.md](../data/README.md)。

使用“截至2026年7月”表述的地图和榜单，若展示年度活动指标，应明确其对应的最近完整报告期；若展示存量，应另注明实际截至日期。外部补充快照保留原始观测期间，不改写为本报告期。周期定义已经主编确认，现有数据文件与该定义的一致性仍需逐图核验，同时检查平台覆盖、对象定义和算法版本的年度可比性。

开发者按照“平台—用户ID”去重，仓库按照“平台—仓库ID”去重。涉及国家和地区分析时，开发者依据公开位置字段进行标准化映射；项目依据发起组织或主要维护组织所在地进行归属。无法可靠识别地理位置或组织归属的数据不进入区域细分统计。

不同平台在事件类型、用户标识和地理字段方面存在差异。本报告首先完成平台内部清洗和去重，再根据分析对象进行汇总。Gitee和AtomGit数据纳入中国国家层面的相关统计；当平台缺少可靠的省市位置数据时，不进入城市级分析。
