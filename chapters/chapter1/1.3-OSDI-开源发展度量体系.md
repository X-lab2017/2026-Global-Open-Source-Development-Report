# 1.3 OSDI：面向智能时代的开源发展目标指标体系

> **本节问题：** 怎样把目标转化为可获取、可解释、可核验的观测，而不是停留在框架图上？

## 1. 从价值坐标到可验证的研究

**开源发展目标指标体系（The OSDGs Indicator System，OSDI）**是 OSDGs 的量化评估框架。它把四大支柱细化为十个维度、二十九项指标，组织关于参与、供给、连接与治理的证据。GOSD 呈现研究成果，OSDGs 明确发展方向，OSDI 则说明观察哪些变化、用什么数据判断。

体系遵循三个原则：目标与指标之间有可解释的关系；数据、方法与结论能够追溯；对不同资产类型和数据覆盖保留必要区分。方法的价值既在于发现趋势，也在于说明一个结论在什么条件下成立。

本期以多维观测、主体比较和具体研究问题为主要呈现方式。二十九项指标不自动合成为一个总分；北极星、诊断、驱动三种角色也不表示计算权重。尚无数据或方法未定的指标继续作为研究方向明确列示。

## 3. 方法基础：把协作过程变成研究证据

### OpenDigger：可追溯的数据与指标基础

OpenDigger 是由 X-lab 发起的开源数据分析与指标生产项目，提供公开指标数据、方法文档和相关实现入口。[1] 本报告以它作为代码生态研究的主要数据与方法基础之一：从平台记录组织行为证据，再通过统一口径形成指标，连接后续图表、榜单与解释。

OpenDigger 的作用不仅是提供一个数值，更是为研究者和社区提供检查定义、追踪来源和继续分析的入口。报告采用的实际数据版本、平台范围与计算方式在 GitHub 中登记；官网提供的方法不应被误写为每份报告文件已经完成的处理。

### OpenRank：区分参与强度、社区贡献与网络影响

三个概念需要分别使用：

| 方法 | 回答的问题 | 本报告中的用途 |
|---|---|---|
| Activity 活跃度 | 发生了多少、何种有效协作行为？ | 补充描述参与强度；与活跃人数分开 |
| 社区 OpenRank 贡献度 | 参与者在项目内的协作网络中怎样贡献？ | 支持代码协作贡献度及社区分析 |
| 全域 OpenRank 影响力 | 开发者与仓库在更大协作网络中处于什么位置？ | 支持代码影响力、主体比较与生态连接分析 |

**表 1.3.3：三类方法的不同用途。** OpenRank 由 X-lab 提出，其价值在于把协作关系纳入分析，而非仅以关注量或行为次数评价主体。[2–4]

社区 OpenRank 利用项目内的 Issue、PR 等协作关系构建网络；全域 OpenRank 则研究开发者与仓库间更广范围的连接，并包含历史继承机制。[3–4] 因而，当期活跃、历史积累和网络地位需要分别解释。将仓库指标进一步用于项目、组织或地区时，还必须说明主体边界和聚合规则，不能省略这一步就直接生成排名。

### ModelRank：面向模型复用网络的方法延伸

模型生态提出了新的关系问题：一个模型被哪些后续模型复用，这些衍生关系怎样继续扩展？ModelRank 在本报告中作为“模型生态衍生力”的研究方向，用于概述从派生与复用网络观察基础模型影响的方法思路。

本轮不设定未经验证的 ModelRank 公式、权重或分数，也不把它写成已经接入 OpenDigger 官网的正式指标。具体关系识别、模型去重、算法版本及结果将在 GOSM 资料补齐后更新。下载数、点赞数与衍生模型数可以分别作为观察信号，但不直接等于 ModelRank。

## 4. 由指标进入研究，由证据形成行动

同一套指标在不同研究板块中承担不同作用。GOSO 重点观察规模与结构；GOSR 需要更严格的主体、样本和排序规则；GOSL 结合技术分类解释网络关系；GOSM 则连接供给、采用、复用与开放治理。第六章提炼这些研究的行动含义，不能由一个指标直接推出政策成效或资源分配结论。

为了让结果可查证，正文的每个定量发现应关联具体图表或数据文件，并能继续追踪到指标定义、统计范围和来源。详细规则放在[附录 A](../../appendices/附录A-指标体系与数据来源.md)，正文保留影响读者判断的范围与限制。

当前仓库已有的 processed 数据主要支持第二章的部分观测。其与二十九项指标之间的对应和差异，列在[数据可用性清单](../../data/meta/数据可用性清单.md)中。本期先把已有证据讲清楚，随数据与方法持续完善扩展覆盖，形成能够逐年积累的开源发展研究基础。
